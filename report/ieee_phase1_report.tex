\begin{abstract}
As semiconductor scaling continues to outpace off-chip memory bandwidth and latency---a disparity widely formalized as the ``memory wall''---the architectural efficiency of processor cache hierarchies has become a paramount determinant of overall computational throughput. In this paper, we present the cycle-accurate design, hardware modeling, and comparative performance evaluation of a synthesizable 128-byte, 2-way set-associative cache with 1-bit Least Recently Used (LRU) replacement against an identically sized direct-mapped cache baseline. Implemented in IEEE 1800-2012 SystemVerilog, both cache microarchitectures utilize a 32-bit byte-addressed memory interface, a 16-byte (4-word) cache-line granularity, blocking single-request execution, and robust valid/ready handshake signaling. The memory subsystem operates with a parameterized multi-cycle latency, enforcing synchronous 4-word burst refills. We subject both architectures to four rigorous synthetic access traces in an automated simulation testbench: sequential spatial locality, conflict-heavy address thrashing, explicit three-address LRU eviction validation, and a realistic mixed-workload trace. Empirical cycle-accurate simulation reveals that under severe conflict thrashing, the 2-way set-associative cache achieves a 75.00\% hit rate and 6.25 cycles per access, whereas the direct-mapped cache suffers a 0.00\% hit rate and 17.50 cycles per access. This yields a 75.00\% reduction in memory traffic (8 versus 32 memory reads) and a 64.29\% reduction in total execution latency (50 versus 140 cycles). These quantitative findings validate the efficacy of set associativity in eliminating conflict misses while confirming the deterministic correctness of our hardware LRU eviction algorithm for modern embedded processor architectures.
\end{abstract}

\section{Introduction}
\IEEEPARstart{O}{ver} the past four decades, microprocessor operating frequencies and execution capabilities have escalated at a substantially higher rate than the access latencies of dynamic random-access memory (DRAM). This persistent performance divergence, famously termed the ``memory wall'' by Wulf and McKee and rigorously documented by Hennessy and Patterson~\cite{hennessy2017computer}, renders high-speed on-chip cache hierarchies indispensable in modern computer architecture. Caches serve as small, fast buffers situated between processor execution pipelines and high-capacity main storage, relying on the dual principles of \textit{temporal locality} (data accessed recently is likely to be accessed again in the near future) and \textit{spatial locality} (data physically adjacent to recently accessed addresses is likely to be referenced shortly)~\cite{smith1982cache}.

According to the classical 3C classification proposed by Mark D. Hill and Alan J. Smith~\cite{hill1989evaluating}, cache misses are categorized into:
\begin{enumerate}
    \item \textit{Compulsory (Cold) Misses}: Unavoidable misses occurring on the initial reference to a block of data that has never resided in the cache.
    \item \textit{Capacity Misses}: Misses occurring when the total working set of an executing program exceeds the aggregate storage capacity of the cache.
    \item \textit{Conflict (Collision) Misses}: Misses occurring when multiple active memory blocks map to the identical cache set or line, forcing premature evictions despite available unoccupied capacity elsewhere in the cache.
\end{enumerate}

Direct-mapped caches represent the simplest placement policy: every physical memory address maps to exactly one predetermined cache line. While direct-mapped caches offer minimal hardware area overhead, simple single-comparator tag checking, and rapid hit detection, they are exceptionally susceptible to catastrophic conflict misses. If a tight loop or interleaved data structure continuously alternates between two distinct memory blocks that hash to the same line index, the cache undergoes continuous ping-pong eviction or ``cache thrashing''~\cite{jouppi1990improving, patterson2020riscv}. Under such conditions, the effective hit rate plunges to zero, degrading system execution throughput to raw memory bus speeds.

Set-associative caches mitigate this vulnerability by organizing cache lines into sets containing $K$ independent slots or ``ways''~\cite{smith1982cache}. In a $K$-way set-associative cache, any given memory block can reside in any of the $K$ ways within its designated set. For $K=2$ (two-way set-associative), up to two conflicting memory blocks can reside simultaneously in on-chip storage without forcing mutual eviction. However, associativity requires a replacement policy to determine which way must be vacated when all ways in a set are valid and a new line must be loaded. The Least Recently Used (LRU) replacement algorithm represents the theoretically optimal online policy under temporal locality assumptions, evicting the line that has experienced the longest period of inactivity~\cite{smith1983instruction}.

In this Phase~I research project, we design, implement, integrate, and validate a cycle-accurate, synthesizable hardware model of both an 8-line (128-byte) baseline direct-mapped cache and a 4-set, 2-way set-associative cache (128-byte total capacity) equipped with a 1-bit LRU replacement controller. Both architectures are developed in IEEE 1800-2012 SystemVerilog and subjected to comprehensive comparative testing against an identical parameterized main memory model under synthetic access patterns. The complete SystemVerilog implementation, testbenches, and reproducibility scripts are available in our project repository: \url{https://github.com/chinmay7980/2-Way-Set-Associative-Cache-with-LRU.git}.

\section{Related Work and Literature Review}
\label{sec:related_work}

The architecture and optimization of cache memories have been extensively investigated since the pioneering surveys by Alan Jay Smith~\cite{smith1982cache}. Smith established the fundamental taxonomy of cache placement rules, write strategies (write-through versus write-back), fetch algorithms (demand fetch versus prefetching), and block replacement schemes, emphasizing that miss ratios decrease monotonically with increased associativity, albeit with diminishing returns.

In their seminal treatise on cache associativity, Hill and Smith~\cite{hill1989evaluating} quantitatively evaluated the performance trade-offs of varying degrees of associativity across real-world instruction and data workloads. They formulated the well-known ``$2:1$ cache rule of thumb,'' which posits that a direct-mapped cache of size $N$ exhibits an empirical miss rate approximately equal to a 2-way set-associative cache of size $N/2$. However, Hill and Smith cautioned that set associativity incurs hardware complexity: parallel tag comparators, wider multiplexers, replacement state logic, and increased critical path delay during the tag-matching cycle. Consequently, direct-mapped caches were historically favored in early pipelined RISC architectures where single-cycle access latency was critical.

Jouppi~\cite{jouppi1990improving} analyzed the specific nature of conflict misses in direct-mapped architectures, demonstrating that high-performance RISC processors frequently experience severe conflict thrashing due to spatial and temporal interference between instructions and loop operands. Jouppi proposed augmenting direct-mapped caches with a small, fully associative ``victim cache'' to rescue evicted blocks, demonstrating that even a minimal 4-entry associative buffer dramatically reduces conflict penalties. This work highlighted that providing alternative placement options for conflicting addresses yields outsized performance dividends.

Replacement policy selection is equally critical. In their comparative evaluation of cache replacement policies, Smith and Goodman~\cite{smith1983instruction} contrasted LRU, First-In First-Out (FIFO), and Random replacement across diverse working sets. Their empirical results demonstrated that true LRU consistently achieves the lowest miss rates for instruction and data caches by exploiting the temporal recurrence of active program segments. For a 2-way set-associative cache, full LRU requires only a single tracking bit per set, eliminating the prohibitive multi-bit matrix overhead associated with higher-order associativities ($K \ge 4$).

Modern computer architecture textbooks, such as Hennessy and Patterson~\cite{hennessy2017computer} and Patterson and Hennessy~\cite{patterson2020riscv}, synthesize these principles into standardized design methodologies. They demonstrate that for contemporary resource-constrained embedded systems, edge Internet-of-Things (IoT) processors, and microcontroller execution units, a 2-way set-associative organization represents an exceptional Pareto-optimal trade-off between hardware silicon overhead and conflict miss mitigation. Our Phase~I investigation builds directly upon these foundational theoretical insights, validating their concrete RTL realization and performance characteristics in hardware.

Both caches share a standardized, synchronous active-low reset interface (\texttt{rst\_n}) and run on a common system clock (\texttt{clk}). The CPU interface implements a single-request blocking protocol:
\begin{itemize}
    \item Input request: \texttt{cpu\_req\_valid} (1 bit), \texttt{cpu\_req\_addr} (32 bits).
    \item Request acceptance: \texttt{cpu\_req\_ready} (1 bit).
    \item Output response: \texttt{cpu\_resp\_valid} (1 bit), \texttt{cpu\_resp\_data} (32 bits).
    \item Response acceptance: \texttt{cpu\_resp\_ready} (1 bit).
\end{itemize}
Handshakes conform to standard ready/valid rules: a transfer is committed on the active clock edge if and only if both \texttt{valid} and \texttt{ready} are asserted simultaneously. The cache guarantees that once \texttt{cpu\_resp\_valid} is raised, both the valid flag and the corresponding \texttt{cpu\_resp\_data} remain perfectly stable until the CPU asserts \texttt{cpu\_resp\_ready}.

\subsection{Direct-Mapped Baseline Architecture}
The baseline direct-mapped cache is implemented in \texttt{rtl/direct\_mapped\_cache.sv} as an integrated monolithic module. Its storage arrays consist of:
\begin{itemize}
    \item \texttt{data\_array[0:7][0:3]}: $8 \times 4 \times 32$-bit storage.
    \item \texttt{tag\_array[0:7]}: $8 \times 25$-bit tag registers.
    \item \texttt{valid\_array[0:7]}: $8 \times 1$-bit validity flags.
\end{itemize}
During the \texttt{LOOKUP} phase, the 3-bit line index \texttt{address[6:4]} selects the corresponding line entry. The stored 25-bit tag is compared against \texttt{address[31:7]}, and the valid bit is inspected:
\begin{equation}
\text{hit} = \text{valid}[\text{idx}] \land (\text{tag\_arr}[\text{idx}] == \text{req\_tag})
\end{equation}
If \texttt{cache\_hit} evaluates to logic~1, the requested 32-bit word is extracted from \texttt{data\_array[index][word\_index]} and forwarded to \texttt{cpu\_resp\_data}, triggering an immediate transition to the \texttt{RESP} state in a single clock cycle. If \texttt{cache\_hit} is logic~0, the cache signals a miss, initiates a 4-word refill from main memory, overwrites the targeted line, updates the tag, and sets the valid bit to 1.

\subsection{Two-Way Set-Associative Datapath Architecture}
The two-way set-associative datapath is implemented in \texttt{rtl/cache\_2way\_datapath.sv}. It decouples the storage arrays and tag-matching comparators from the control sequencing logic. The datapath instantiates two parallel ways (Way~0 and Way~1) across four sets:
\begin{itemize}
    \item Way~0 Storage: \texttt{data\_array\_w0[0:3][0:3]}, \texttt{tag\_array\_w0[0:3]}, and \texttt{valid\_array\_w0[0:3]}.
    \item Way~1 Storage: \texttt{data\_array\_w1[0:3][0:3]}, \texttt{tag\_array\_w1[0:3]}, and \texttt{valid\_array\_w1[0:3]}.
\end{itemize}

Fig.~\ref{fig:datapath_diagram} illustrates the parallel tag comparison and data selection circuitry. For a registered set index \texttt{set\_idx = address[5:4]}, the datapath performs concurrent tag comparisons across both ways:
\begin{align}
\text{hit\_w0} &= \text{valid\_w0}[\text{set}] \land (\text{tag\_w0}[\text{set}] == \text{req\_tag}) \\
\text{hit\_w1} &= \text{valid\_w1}[\text{set}] \land (\text{tag\_w1}[\text{set}] == \text{req\_tag}) \\
\text{cache\_hit} &= \text{hit\_w0} \lor \text{hit\_w1}
\end{align}

Because a memory address can match at most one valid way at any given instant (guaranteed by our mutual-exclusion allocation invariants), \texttt{hit\_way0} and \texttt{hit\_way1} are strictly mutually exclusive. If \texttt{hit\_way0} is asserted, \texttt{hit\_way\_select} evaluates to 0, routing the selected word from Way~0; if \texttt{hit\_way1} is asserted, \texttt{hit\_way\_select} evaluates to 1, routing the word from Way~1.

\subsection{1-Bit LRU Replacement Controller}
The LRU replacement controller is implemented as an independent hardware module in \texttt{rtl/lru\_controller.sv}. For a 2-way set-associative cache, full LRU tracking requires exactly 1 bit of replacement state per set:
\begin{equation}
\text{LRU Array: } \text{lru\_bits}[0:3], \quad \text{Width} = 1\text{ bit per set}
\end{equation}

The architectural convention adopted throughout our design is strictly formalized as:
\begin{itemize}
    \item $\text{lru\_bits}[\text{set}] = 0$: Way~0 was least recently accessed; Way~0 is the replacement candidate.
    \item $\text{lru\_bits}[\text{set}] = 1$: Way~1 was least recently accessed; Way~1 is the replacement candidate.
\end{itemize}

Whenever an access occurs to a set (either a cache hit during \texttt{LOOKUP} or a newly completed refill during \texttt{RESP}), the replacement bit is deterministically updated:
\begin{equation}
\text{lru\_bits}[\text{set}] \leftarrow \begin{cases}
1, & \text{if Way 0 accessed}, \\
0, & \text{if Way 1 accessed}.
\end{cases}
\end{equation}

Crucially, the replacement controller enforces an \textit{invalid-first allocation priority} before consulting the LRU bit:
\begin{equation}
\text{replace\_way} = \begin{cases}
0, & \text{if } \neg\text{v\_w0}[\text{set}], \\
1, & \text{if } \text{v\_w0}[\text{set}] \land \neg\text{v\_w1}[\text{set}], \\
\text{lru}[\text{set}], & \text{if } \text{v\_w0}[\text{set}] \land \text{v\_w1}[\text{set}].
\end{cases}
\end{equation}
This hardware rule guarantees that empty (invalid) cache ways are always populated first upon initial cold accesses, entirely preventing premature evictions of valid working data.

\begin{enumerate}
    \item \textbf{IDLE}: The cache asserts \texttt{cpu\_req\_ready = 1}. Upon detecting \texttt{cpu\_req\_valid = 1}, the controller latches \texttt{cpu\_req\_addr} into internal registers and transitions to \texttt{LOOKUP}.
    \item \textbf{LOOKUP}: The datapath performs parallel tag comparison. If \texttt{cache\_hit} is true, \texttt{hit\_count} increments, the LRU state updates to reflect the accessed way, and the FSM branches directly to \texttt{RESP}. If \texttt{cache\_hit} is false, \texttt{miss\_count} increments, the victim way is evaluated via \texttt{replace\_way}, the word refill counter \texttt{refill\_word\_cnt} is reset to 0, and the FSM transitions to \texttt{MEM\_REQ}.
    \item \textbf{MEM\_REQ}: The controller generates a word read request to main memory, asserting \texttt{mem\_req\_valid = 1} with \texttt{mem\_req\_addr} aligned to the 16-byte boundary. When the memory asserts \texttt{mem\_req\_ready = 1}, \texttt{mem\_word\_read\_count} increments, and the FSM transitions to \texttt{MEM\_WAIT}.
    \item \textbf{MEM\_WAIT}: The controller sets \texttt{mem\_resp\_ready = 1} and waits for \texttt{mem\_resp\_valid = 1}. Upon receiving data, the 32-bit word is written to \texttt{data\_array} at \texttt{[replace\_way][latched\_set][refill\_word\_cnt]}. If \texttt{refill\_word\_cnt < 3}, \texttt{refill\_word\_cnt} increments, and the FSM loops back to \texttt{MEM\_REQ} for the next word. When \texttt{refill\_word\_cnt == 3}, the final word is written, the tag array is updated with \texttt{latched\_tag}, the valid bit is set, the LRU bit is updated to point away from \texttt{replace\_way}, and the FSM transitions to \texttt{RESP}.
    \item \textbf{RESP}: The cache drives \texttt{cpu\_resp\_valid = 1} and outputs the requested 32-bit word on \texttt{cpu\_resp\_data}. Both signals remain asserted until the CPU raises \texttt{cpu\_resp\_ready = 1}, whereupon the FSM returns to \texttt{IDLE}.
\end{enumerate}

\subsection{Main Memory Subsystem and Burst Refill Protocol}
Main memory is modeled in \texttt{sim/simple\_main\_memory.sv} as an on-chip synchronous SRAM comprising 1024 32-bit words (4~KB addressable space). Memory data initialization follows a deterministic arithmetic pattern:
\begin{equation}
\text{memory\_array}[i] = 32'\text{hA5000000} \oplus i, \quad i \in [0, 1023]
\end{equation}
This deterministic structure allows the verification environment to independently calculate the exact expected data word for any byte address:
\begin{equation}
\text{Expected Data} = 32'\text{hA5000000} \oplus \left( \frac{\text{address}}{4} \right)
\end{equation}
The memory controller implements a parameterized fixed access latency (\texttt{LATENCY\_CYCLES = 2}) and back-to-back request delay (\texttt{REQUEST\_GAP\_CYCLES = 1}), accurately emulating realistic DRAM/SRAM timing penalties. When a cache line refill occurs, four consecutive read requests are issued to memory addresses aligned to 16-byte boundaries ($\text{word\_idx} = 0, 1, 2, 3$).

\subsection{Experimental Setup and Verification Methodology}
The verification suite is executed using the open-source Icarus Verilog (v12.0) compiler and simulation runtime engine. All testbenches are compiled with standard IEEE 1800-2012 flags (\texttt{-g2012 -Wall}). Both the direct-mapped cache and the 2-way set-associative cache are instantiated in parallel inside \texttt{tb/tb\_cache\_comparison.sv} and driven concurrently by independent CPU driver threads.

The testbench incorporates two vital verification features:
\begin{enumerate}
    \item \textbf{Address Poisoning}: After a request is accepted on \texttt{cpu\_req\_ready}, the address bus is immediately overwritten with \texttt{32'hFFFF\_FFFF} on the subsequent negative clock edge. This ensures that the cache internal logic correctly latches the address and does not suffer from transparent latch errors or combinational leakage.
    \item \textbf{Randomized Response Backpressure}: During selected accesses, the CPU driver artificially delays asserting \texttt{cpu\_resp\_ready} for multiple clock cycles, verifying that the cache controller holds \texttt{cpu\_resp\_valid} and \texttt{cpu\_resp\_data} perfectly stable without dropping data.
\end{enumerate}

Every executed transaction asserts two fundamental microarchitectural invariants:
\begin{align}
\text{hit\_count} + \text{miss\_count} &= \text{Total Completed Accesses} \\
\text{mem\_word\_read\_count} &= 4 \times \text{miss\_count}
\end{align}
Failure of either invariant triggers an immediate simulation \texttt{\$fatal} termination.

\subsection{Benchmark Scenarios and Quantitative Results}
We evaluate both caches across four carefully constructed synthetic access traces representing canonical program access behaviors:
\begin{itemize}
    \item \textbf{Scenario 1: Sequential Spatial Locality (4 Accesses)}: Sequential word reads within the identical 16-byte block: addresses \texttt{0x00000000}, \texttt{0x00000004}, \texttt{0x00000008}, and \texttt{0x0000000C}.
    \item \textbf{Scenario 2: Conflict-Heavy Trace (8 Accesses)}: Alternating references between two addresses that map to the identical cache set: \texttt{0x00000000} and \texttt{0x00000080} repeated four times.
    \item \textbf{Scenario 3: Explicit Three-Address LRU Validation (6 Accesses)}: A canonical sequence $A \to B \to A \to C \to A \to B$ where $A = \texttt{0x00000000}$, $B = \texttt{0x00000080}$, and $C = \texttt{0x00000100}$. All three blocks map to Set~0 in the 2-way cache and Line~0 in the direct-mapped cache.
    \item \textbf{Scenario 4: Mixed Workload Trace (16 Accesses)}: A complex trace exercising spatial stride, multi-set accesses across sets 0, 1, 2, and 3, and temporal reuse.
\end{itemize}

\subsection{Detailed Architectural Analysis}

\subsubsection{Scenario 1: Sequential Spatial Locality}
In Scenario~1, both architectures exhibit identical performance: 3 hits and 1 miss (75.00\% hit rate), requiring 4 memory reads and 27 clock cycles (6.75 cycles/access). The initial access to address \texttt{0x00000000} results in a compulsory cold miss. The cache controller fetches four consecutive 32-bit words from main memory, populating the entire 16-byte line. Subsequent accesses to offsets \texttt{0x4}, \texttt{0x8}, and \texttt{0xC} immediately hit in the cache, requiring only a single-cycle lookup. This demonstrates the spatial locality benefit of multi-word cache lines: the initial miss penalty is amortized across subsequent word accesses within the line.

\subsubsection{Scenario 2: Conflict-Heavy Thrashing Elimination}
Scenario~2 provides dramatic quantitative proof of the superiority of set associativity. Addresses \texttt{0x00000000} and \texttt{0x00000080} both have index bits \texttt{3'b000} in the direct-mapped cache, but differing tags (\texttt{0x000000} versus \texttt{0x000001}). In the direct-mapped cache, every single access evicts the resident block loaded by the immediately preceding access. This catastrophic thrashing results in 8 misses out of 8 accesses (0.00\% hit rate), triggering 32 memory reads and consuming 140 clock cycles (17.50 cycles/access).

In the 2-way set-associative cache, both addresses map to Set~0 (\texttt{set\_idx = 2'b00}), but have tags \texttt{0x000000} and \texttt{0x000002}. During the first two accesses, address \texttt{0x00000000} populates Way~0 and address \texttt{0x00000080} populates Way~1 via the invalid-first allocation rule. For the remaining six accesses, both lines reside simultaneously in Set~0. As a consequence, accesses 3 through 8 result in instantaneous cache hits. The 2-way cache achieves:
\begin{itemize}
    \item Hit rate increase from 0.00\% to 75.00\%.
    \item Memory word reads reduced from 32 to 8 (a \textbf{75.00\% reduction} in memory bus traffic).
    \item Total latency reduced from 140 cycles to 50 cycles (a \textbf{64.29\% speedup}).
\end{itemize}

\subsubsection{Scenario 4: Mixed Workload Dynamics}
Scenario~4 exercises multi-set spatial distribution and capacity limits across 16 accesses. Both caches yield identical macroscopic results: 4 hits and 12 misses (25.00\% hit rate, 48 memory reads, 216 execution cycles). This occurs because the working set size exceeds the 2-way associativity limit for specific sets, causing capacity-induced evictions in both structures. This finding highlights a fundamental principle of computer architecture: while set associativity eliminates conflict misses up to degree $K$, it cannot eliminate capacity misses once the active working set surpasses the physical capacity of the set.

\section{Conclusion and Future Work (Phase II)}
\label{sec:conclusion}

In this Phase~I investigation, we successfully designed, modeled, integrated, and empirically validated a 128-byte, 2-way set-associative cache with 1-bit LRU replacement against an identically configured direct-mapped baseline cache in IEEE 1800-2012 SystemVerilog. The experimental evaluation confirms that set associativity completely eliminates ping-pong cache thrashing under conflicting access patterns, elevating the hit rate from 0.00\% to 75.00\%, decreasing memory traffic by 75.00\%, and reducing total execution latency by 64.29\%. Furthermore, cycle-by-cycle testing of an explicit three-address conflict trace ($A \to B \to A \to C \to A \to B$) established the deterministic correctness of our invalid-first allocation priority and 1-bit LRU tracking algorithm.

\subsection{Phase II Development Roadmap}
Building upon the verified read-only baseline established in Phase~I, our Phase~II development roadmap encompasses:
\begin{enumerate}
    \item \textbf{Write Policy Integration}: Implementation of write-through with write buffers and write-back with dirty bits (\texttt{dirty\_array}), requiring cache-line write-back FSM sequences to main memory.
    \item \textbf{Non-Blocking Cache Extensions}: Integration of Miss Status Holding Registers (MSHRs) to support hit-under-miss and miss-under-miss concurrency, enabling pipelined memory requests.
    \item \textbf{Higher-Order Associativity}: Exploration of 4-way set-associative configurations using Pseudo-LRU (tree-PLRU) replacement policies to assess area-latency scaling.
    \item \textbf{Physical FPGA Implementation}: Synthesis, placement, routing, and timing closure on an AMD/Xilinx Artix-7 (XC7A35T) FPGA development board to measure exact Look-Up Table (LUT), Flip-Flop (FF), Block RAM (BRAM), and maximum operating frequency ($F_{\max}$) trade-offs.
\end{enumerate}
